# Repository Guidelines

## Project Structure & Module Organization
- `src/`: TypeScript source code.
- `src/providers/`: Provider-specific API adapters.
- `tests/`: Vitest test suite.
- `dist/`: Build output (generated by `tsc`).
- Config files at the repo root: `tsconfig.json`, `eslint.config.js`, `.prettierrc`.

## Build, Test, and Development Commands
- `npm run build` compiles TypeScript into `dist/`.
- `npm run dev` runs the built entrypoint with Node watch mode.
- `npm test` runs the Vitest suite once.
- `npm run test:watch` runs tests in watch mode.
- `npm run lint` checks linting rules.
- `npm run format` formats the codebase with Prettier.

## Coding Style & Naming Conventions
- Indentation: 2 spaces.
- Use `camelCase` for variables/functions and `PascalCase` for types/classes.
- File naming: `kebab-case` or `camelCase` for modules; test files end with `.test.ts`.
- Formatting is handled by Prettier; linting by ESLint.

## Testing Guidelines
- Framework: Vitest.
- Tests live in `tests/` and use `*.test.ts` naming.
- Prefer small, focused unit tests; add integration tests only when needed.

## Commit & Pull Request Guidelines
No commit convention is established. If you add one, update this section.

Pull requests should include:
- A clear summary of changes
- Linked issues or tasks, when applicable
- Screenshots or logs for UI or behavior changes

## Security & Configuration Tips
Keep secrets out of the repo. If needed, use `.env` and commit a `.env.example`.
OpenAI calls require `OPENAI_API_KEY` in the environment; `.env` is loaded via `dotenv`.

## Agent-Specific Instructions
When editing, keep this document up to date with any new scripts, tooling, or structure.
